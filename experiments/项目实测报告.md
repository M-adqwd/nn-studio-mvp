# 医疗 AI 一体化平台 · 实测报告（Day 0 – Day 7）

> 目标：用客户真实会提的两类任务（视网膜病变分级 / 心电图判读），
> 验证「数据 → 训练 → 模型仓库 → 推理 → 阅片报告」这条链路是否真的成立。
> 结论先行：**两个任务都能承接，但当前跑出来的数字只能证明工程链路，
> 不能当作临床性能对外承诺**（原因见第 6 节）。

---

## 1. 结论摘要

| 任务 | 平台能否承接 | 实测结果（独立测试集，全程未参与训练） | 结论 |
|---|---|---|---|
| 视网膜病变分级（5 级） | ✅ 能 | acc **0.729** · macro-F1 **0.652** · **QWK 0.817**（413 张） | 可作辅助提示，QWK 达到「良好」区间 |
| 心电图 12 导联多标签判读 | ✅ 能（本次新增信号通路） | macro-**AUC 0.881** · macro-F1 0.677（799 条，官方 fold 10） | 达到同规模 1D CNN 的公开水平 |
| 心电图单导联心搏分类 | ⚠️ 能跑，但指标不可信 | acc 0.806 · macro-F1 0.467 · QWK 0.665 | 按患者切分后 F 类训练样本只剩约 36 条，学不出来 |
| 两套系统打通 | ✅ 已打通 | 模型结论 → 病例 → draft 报告（带模型名/版本/概率引用） | 眼底与心电两条模态都验证通过 |
| 门禁改造（SOP v2.0） | ✅ 已落地 | 12 个审计样本全部按预期拦截；回归门 27/27 | 平台从「什么都能训」变成「会拒绝」 |

**一句话对外口径**：
「平台可在客户自有数据上完成训练—验证—部署全流程，并给出可追溯的辅助结论；
临床性能需在客户目标人群上用患者级独立测试集重新标定。」

## 2. 实测结果明细

### Day 0 · MIT-BIH 心搏分类（零改动跑通链路）
- 数据：MIT-BIH 心律失常库 → 187 点 × 4 类（N/S/V/F），10 万级样本
- 路径：表格分类（HistGradientBoosting），**未改一行代码**
- 结果：val acc **0.988** / macro-F1 **0.901**
- 意义：证明平台本身没坏；同时暴露「随机切分把同一病人的心搏分到训练与测试」的指标虚高问题（Day 5 复现）

### Day 1 · 眼底 2750 张 5 级基线
- 数据：APTOS 子集 224px，5 级，2750 张
- 结果：链路通，但任务被平台静默回退覆盖（见缺陷 3）
- 意义：这一天最大的产出不是指标，而是 3 个 P0 缺陷

### Day 2 · 眼底 + 独立测试集 + QWK
- 切分：自带 train/val/test（1924 / 413 / 413），平台校验「413 张测试样本与训练零交集」
- 第 1 轮：MobileNetV3-Small @224 微调 → test acc 0.724 / F1 0.623 / QWK 0.749
- 第 2 轮：ResNet18 @256 微调 → **test acc 0.729 / F1 0.652 / QWK 0.817**
- 说明：QWK 0.817 属「良好（good）」区间；这是本项目唯一可直接写进材料的分级指标
- 注：当次训练的测试集 QWK 未落库（平台缺陷 9），该值由保存的 413×413 混淆矩阵精确复算
  （`sklearn.cohen_kappa_score(weights="quadratic")`），不是估算；缺陷已修，重跑会直接输出

### Day 4 · PTB-XL 12 导联多标签（新增 1D 信号通路）
- 数据：PTB-XL 1.0.3，抽 8000 条（12 导联 × 1000 点 = 12000 列），官方 strat_fold 9/10 做验证/测试
- 标签：5 大超类多标签（NORM/MI/STTC/CD/HYP），多标签占比 23.6%
- 模型：1D CNN，逐条 z-score，BCE + 正样本加权，逐类阈值在验证集标定
- 结果：**test macro-AUC 0.881 / macro-F1 0.677**（799 条）
- 阈值：CD 0.60 / HYP 0.60 / MI 0.45 / NORM 0.75 / STTC 0.70

### Day 5 · 单导联心搏走信号通路（同一套代码）
- 结果：acc 0.806 / macro-F1 0.467 / QWK 0.665
- 关键发现：按 `patient` 分组切分后，F 类在训练集只剩约 36 条（全库 802 条，748 条落在测试集），
  F1 = 0.003 —— **不是模型不行，是数据饥饿**
- 反证：Day 0 随机切分 macro-F1 0.901，正是病人级泄漏造成的虚高

### Day 6 · 一体化打通
- 新增通用 AI 网关（ModelForge 侧）：`/api/gateway/catalog`、`/api/gateway/infer`
- 新增分类结论通路（MIIS 侧）：`POST /api/v1/ai/classify` → AiJob(done) + **draft 报告**
- 验证（真实调用，非 mock）：
  - 眼底图 → 「糖尿病视网膜病变 2 级（中度），置信度 61.28%」→ draft 报告，refs 指向 ai_job
  - 12 导联心电 → 「检出 心肌梗死（MI），置信度 57.94%」→ draft 报告
- 语义：报告文本由网关翻译（分级/心搏类别/超类），医生不需要看 `2_moderate` 这种原始标签

### Day 7 · 门禁改造（SOP v2.0）与复测
- 起因：拿 12 个构造样本打上传接口，发现 **7 个内容级错误返回 200**，报错要等异步解析才暴露；
  更严重的是单类别、标签泄漏、把信号列当标签这三类垃圾数据**全部训练「成功」**
- 改造：按 `docs/SOP.md` 落地 G0 接收预检 → G1 画像门 → G2 切分门 → G3 训练准入 → G4 评估门 → G5 发布门 → G7 退役门
- 复测（12 个样本，逐条对比见表）：7 个内容错误全部在**同步阶段**被拒并带稳定错误码；
  三个垃圾数据集状态变为 `needs_fix`，建任务直接被 `E5002` 拦下
- 回归：`scripts/sop_regression.py` **27 项断言全过**（2026-10-31 复跑），
  眼底 DR 与肺炎筛查两个真实数据集**未被误伤**
- 发布门实测：DR 五级（F1 0.652 / QWK 0.817）与 PTBXL（AUC 0.881）进 production；
  MIT-BIH 单导联 F1 0.456 被 rejected；肺炎模型因缺独立测试集指标被拒
- 仍未落地：G6 金丝雀推理、前端错误码展示、训练侧消费「已确认切分方案」
  （明细见 SOP §11 末尾）

### Day 7 的一条副产品结论
门禁不是靠"更聪明的模型"实现的，而是靠**本地规则 + 稳定错误码**。
审计里 7 个内容错误全部可以用魔数、字节数、zip 目录结构、编码嗅探判定，
不需要大模型——而当时它们全部被送去大模型，大模型 401 就整链失败。
「确定性优先于智能」这条原则，在这一轮里被实测数据逼出来的。

## 3. 本次修掉的平台缺陷（12 个，全部为实跑暴露）

| # | 缺陷 | 后果 | 处理 |
|---|---|---|---|
| 1 | BatchNorm 遇单样本批直接抛错 | 眼底训练首次必崩 | 批切分保证每批 ≥2 条 |
| 2 | SQLite WAL 在 E 盘报只读 | 45 分钟训练中断 | 改 DELETE 模式 + 长 busy_timeout |
| 3 | 自动建模失败后静默回退基础训练 | 72% 的模型被 60% 顶掉，仍标「成功」 | 保留日志 + 指标标注 `fallback` |
| 4 | 多轮迭代方案不递进 | 第 2/3 轮原样重跑，白烧 25 分钟 | 基于上一轮方案逐级加大容量 |
| 5 | 图像输入硬上限 224px | 眼底微病变在 224px 下消失 | 改为可配置（已跑到 256px） |
| 6 | 宽表提示词爆炸（12000 列） | AI 画像提示词几 MB | 列分组摘要，压到 4.8KB |
| 7 | 大模型 401 导致表格完全无法入库 | PTB-XL 600MB 表直接卡死 | 新增平台直读（4.3 秒读完，不依赖 AI） |
| 8 | 信号任务未进自动建模白名单 | 12000 列喂给 MLP，acc 仅 0.42 | 纳入路由，并在基础路径显式拒绝 |
| 9 | 微调路径测试集不算 QWK | 客户问 kappa 答不上来 | 测试集一并输出 QWK |
| 10 | 多标签推理标签与置信度错位 | 「报 MI，概率却是 STTC 的」 | 阈值命中后按概率排序并对齐 |
| 11 | 记忆库仅按目录形状匹配 | 不同表复用别人的解析脚本 | 增加列结构校验 |
| 12 | 报告引用类型缺「AI 结论」 | 模型结论进不了证据链 | 新增 `ai_job` 引用（仅 done 态可引） |

## 4. 一体化架构（打通后的形态）

```
┌───────────────────────┐        ┌──────────────────────────┐
│  ModelForge（训练）    │        │  MIIS（阅片/报告）        │
│  数据集 → 训练 → 模型  │        │  病例 → SEG/测量 → SR     │
│  /api/gateway/catalog │◄───────│  adapters/modelforge.py  │
│  /api/gateway/infer   │  统一   │  POST /api/v1/ai/classify│
└───────────────────────┘  信封    └──────────────────────────┘
        │                                    │
        └── 模型名/版本/概率/免责声明 ────────┘
                    ↓
            AiJob(done) → draft Report(refs: ai_job)
                    ↓
              医师复核 → 签发 SR
```

关键设计：
- **网关不写临床库**，只产出建议性结论；报告落库、状态流转、签发全部留在 MIIS
- **draft 态强制**：AI 不能签发报告，只能生成草稿
- 模型版本、概率向量、免责声明全部进 `AiJob.stats`，可追溯

## 5. 环境限制（必须在材料中如实写明）

1. **CPU-only，无 GPU**：本次最大输入 256px、PTB-XL 仅取 8000 条。上 GPU 后分辨率与数据量都能翻数倍。
2. **大模型服务不可用**（provider 返回 401 invalid api key）：本次全部走规则路径 / 平台直读，
   AI 辅助解析能力未参与验证。
3. 眼底数据为 APTOS 子集（印度人群、单一相机），心电为 PTB-XL（德国单中心）。
4. 眼底数据无患者 ID，**未能做患者级切分**；只有心电做到了（也因此暴露了 F 类饥饿问题）。

---

## 6. 对外口径与风险（建议写进标书/合同的边界）

1. **「能跑 demo」≠「能过临床验收」**。上述数字证明的是工程链路与可复现性，
   不构成目标人群上的临床性能承诺。
2. 眼底分级与心电判读均属**辅助诊断**，涉及二类/三类医疗器械。
   平台作为「训练与验证工具」不涉证；一旦以「判定」名义对外，需走注册路径。
3. 建议在合同中明确：性能指标以**客户目标人群、患者级独立测试集**重新标定后为准。
4. 心电若要做成临床可用的节律判读，还需补：多导联节律级建模、患者级切分策略、
   少数类过采样或分层采样（否则 F 类永远学不出来）。

## 7. 复现方式

```bash

cd nn-studio-mvp/backend
NN_MAX_IMG_SIZE=320 NN_MAX_ROUNDS=2 ../.venv/Scripts/python.exe -m uvicorn main:app --port 8000

# 阅片平台（指向训练平台网关）
# 密码取训练平台首次启动时的 NN_ADMIN_PASSWORD（未设置则用开发默认口令）
cd medical-imaging-mvp/server
MODELFORGE_BASE_URL=http://127.0.0.1:8000 \
MODELFORGE_ACCOUNT=admin MODELFORGE_PASSWORD="$NN_ADMIN_PASSWORD" \
.venv/Scripts/python.exe -m uvicorn app.main:app --port 8100

# 回归门（改 SOP 或改门禁后必跑）
./.venv/Scripts/python.exe scripts/sop_regression.py

# 一体化联调（眼底 / 心电）
python nn-studio-mvp/scripts/e2e_integration.py \
  --image "_data/fundus/dr_split/test/3_severe/*.png" --model "眼底DR五级-DAY2"
python nn-studio-mvp/scripts/e2e_integration.py \
  --ecg _data/ecg/ptbxl/ptbxl_12lead.csv --model "PTBXL-12导联多标签-信号路径"
```
